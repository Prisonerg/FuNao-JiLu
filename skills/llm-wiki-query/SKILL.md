# LLM Wiki Query —— 基于 wiki 综合回答

本 skill 指导你基于 GBrain-core Wiki 的现有知识网络，综合回答用户的知识性问题。你是 wiki 维护者，遇到提问先翻 wiki 再回答，不凭空编造。

**权威依据**：`/workspace/AGENTS.md`（GBrain-core Wiki Schema 规范）。本 skill 是其中 §9.2 的工作流展开，遇到任何未尽事宜以 AGENTS.md 为准。

## 触发条件

- 用户说「查一下 xxx」「wiki 里有没有关于 xxx 的」「根据 wiki 回答」「问一下」
- 用户提出一个知识性问题，且该问题可能触及 wiki 已覆盖的内容

**不触发**：代码任务、与 wiki 无关的普通问题、闲聊。

## Query 工作流（7 步）

**权威依据**：AGENTS.md §9.2。完整步骤以 AGENTS.md 为准，本节列特有注意事项。

### 步骤 1-2：先读 index.md + 全量关键词扫描（不依赖 index 登记）

- 读 `wiki/index.md` 了解 wiki 覆盖范围与主题 MOC。
- **index 可能漏登记**，MUST 用 Grep 工具搜 `wiki/*.md` 的标题（`# ` 开头行）、frontmatter 的 `title` 与 `tags` 字段。
- 中文与英文关键词都搜（如同时搜「UHPC」与「超高性能混凝土」），不只搜精确匹配，也搜语义相关词。

### 步骤 3-4：读编译真相区 + 综合多页回答

- 对扫到的相关页，读其编译真相区（`## 时间线` 以上）。如需了解结论演变或证据链，再读 `## 时间线` 区。
- **不要只依赖单页**——尝试综合多个相关页的编译真相。不同页对同一问题有不同角度时，整合呈现。
- 发现页间矛盾时在回答中指出并建议用户裁定（触发 lint 的矛盾检查）。

### 步骤 5：引用具体页 + 暴露知识缺口

- **引用**：回答中用 `[[xxx]]` 或 `[[xxx|显示文本]]` 标注信息来自哪个 wiki 页。引用格式与交叉引用风格以 **AGENTS.md §6** 为准。
- **暴露缺口**：若问题触及 wiki 未覆盖的内容，**绝不编造**，明确告诉用户「这块 wiki 还没有，你可以 ingest 相关源」。若缺口是用户刚在对话里提到的实体/概念，可提示是否要 ingest。

### 步骤 6：数据可追溯性

- 回答中每个关键论断 SHOULD 能追溯到某个 wiki 页的编译真相。
- 若用户追问数据来源，可进一步指向该页 frontmatter 的 `sources`（指向 `raw/` 文件）。
- 若数据来自 `reliability: low` 或 `medium` 的源，适当提示可信度。
- 引文格式以 **AGENTS.md §7** 为准。

### 步骤 7：评估回填价值

回答完成后，评估本次回答**是否产生了值得回填的新综合**。回填是把 query 产生的新综合固化回 wiki 的机制，避免高价值综合随会话蒸发。

**主动询问回填的判据**（满足任一即主动询问）：
- 综合了 **3+ 个 wiki 页**的编译真相
- 产生了**新的对比**（页与页之间未被 wiki 记录的对照关系）
- 产生了**新的连接**（跨域/跨主题的新关联）
- 产生了**新的框架/洞见**（用户在问答中冒出的原创综合，亦触发 §13 original 主动捕获）

询问话术示例：「这次回答综合了 [[a]]、[[b]]、[[c]] 三页并形成了新的对比/框架，是否要回填为 summary/original 页？」

**用户同意后回填流程**：
1. 判定 type：综合多源对比 → `summary`（§4.4）；用户原创洞见 → `original`（§4.7）。
2. 按对应 type 模板新建一页，含双区结构（§4.1）。
3. **frontmatter `sources` 用 `[[xxx]]` 列出源 wiki 页**（而非 raw 文件，因为本次综合的「源」是 wiki 页本身；若同时引用了 raw，亦一并列出）。
4. `## 时间线` 首条记录本次回填事件，来源标注「User, query 回填, [[a]]/[[b]]/[[c]]」。
5. index.md 对应 domain × type 分组登记、最近更新追加、标签索引刷新（§10）。
6. **log.md 追加一条 `query-fileback` 记录**（不是 `query`，专用于回填事件）：

```markdown
### YYYY-MM-DD HH:MM - Query-fileback

- **源文件**：—（无新 raw 源；本次综合来自 query）
- **触达的 wiki 文件**：wiki/new-page.md, wiki/a.md（仅追加时间线条目，如适用）, …
- **说明**：用户问 X，综合 [[a]]/[[b]]/[[c]] 后回填为新页 [[new-page]]（type）。log.md 时间戳用 24 小时制 Asia/Shanghai。
```

**不强制回填**：仅复述单页内容、或未产生新综合（无新对比/连接/框架）时，**MUST NOT** 建议回填，避免噪音。

## 多形态输出指引

根据问题性质选择最合适的输出形态，不必总是纯文本：

| 问题形态 | 推荐输出形态 | 工具 |
| --- | --- | --- |
| 对比类（A vs B vs C） | 表格 | Markdown 表格 |
| 趋势类（随时间/参数变化） | 图表 | matplotlib 生成 PNG |
| 汇报类（需结构化呈现） | Marp 幻灯片 | Marp markdown |
| 关系网络类（多实体互链） | canvas 图谱 | Obsidian canvas / 网络图 |
| 一般知识问答 | 纯文本 + `[[wikilink]]` 引用 | Markdown |

输出非文本形态时，仍须在 wiki 页（或对话）中保留可追溯的 `[[wikilink]]` 引用。

## 通用规则（以 AGENTS.md 为准）

以下通用规则不在本 skill 重复：
- 交叉引用风格（`[[filename]]` / 禁止相对路径）：**§6**
- 引文格式（sources 三层互补）：**§7**
- 双区结构（若回填建页）：**§4.1**
- 领域感知（ai 可公开 / personal 含隐私 / hobby 可公开）：**§12**

## 何时记录到 log.md

- 简单问答可不记。
- **回填事件**：MUST 记 `query-fileback`（见步骤 7）。
- **复杂 query 未回填**：若综合了 3+ wiki 页、暴露了重要缺口、发现了页间矛盾但未回填，可在 `wiki/log.md` 追加一条 `query` 记录（§11），说明用户问了什么、综合了哪些页、是否暴露缺口。
