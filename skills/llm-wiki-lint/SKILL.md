# LLM Wiki Lint —— 体检与修复

本 skill 指导你对 GBrain-core Wiki 进行全面体检（lint），发现并修复结构完整性、互链健康度、内容一致性方面的问题。你是 wiki 维护者，既要运行机器化检查，也要做 LLM 才能做的语义检查。

**权威依据**：`/workspace/AGENTS.md`（GBrain-core Wiki Schema 规范）。本 skill 是其中 §9.3 + §14 的工作流展开，遇到任何未尽事宜以 AGENTS.md 为准。

## 触发条件

- 用户说「lint wiki」「体检一下 wiki」「检查 wiki 一致性」「找找孤岛页」「找找矛盾」
- `scripts/wiki-lint.sh` 被运行
- Trae Schedule 定期自动触发

## Lint 工作流

**权威依据**：AGENTS.md §9.3（机器化 8 项 + LLM 补充 4 项）、§14（机器化维护）。

### 第一部分：机器化检查（由 scripts/wiki-lint.sh 执行）

运行体检脚本：

```bash
bash scripts/wiki-lint.sh
```

脚本（纯 bash/grep，无外部依赖）执行 **8 项检查**（详见 §9.3）：

1. frontmatter 完整性（必填字段齐全、type/domain 取值合法）—— 对应 §3
2. 双区结构（每页含 `## 时间线` 二级标题）—— 对应 §4.1
3. 孤岛页（无任何 `[[wikilink]]` 指向它）—— 对应 §6
4. 悬空引用（`[[xxx]]` 指向不存在的页）—— 对应 §6
5. sources 与 raw 对齐（frontmatter `sources` 列的文件在 `raw/` 下存在）—— 对应 §3、§7
6. index 与实际页对齐（index 登记的页存在、实际页都在 index 登记）—— 对应 §10
7. 时间线格式（条目含日期与来源标注）—— 对应 §4.1、§7
8. 反向链接矩阵（输出谁指向谁）—— 对应 §6

读取脚本输出，记录错误数与警告数。退出码 0 = 无错误，1 = 有错误。

### 第二部分：LLM 补充检查（机器无法做的，由 LLM 执行）

机器检查通过后，继续做以下 **4 项语义检查**（详见 §9.3）：

1. **找矛盾**：同一实体在不同页编译真相说法不一致 → 按 §8 处理（时间线追加修正条目 + 重写编译真相 + 必要时 callout + log.md 记录）。
2. **找过时声明**：某页 `updated` 日期过久，且其 `sources` 指向的 `raw/` 文件有更新 → 标记并重新整合。
3. **找缺失交叉引用**：某实体在正文被提及但没建 `[[wikilink]]` → 补链。
4. **检查编译真相与时间线一致性**：编译真相的论断是否都有时间线条目支撑 → 若无支撑，补充时间线条目。

### 第三部分：输出体检报告

汇总机器检查与 LLM 检查结果，输出结构化报告：

```
## Lint 体检报告

### 机器化检查（wiki-lint.sh）
- 页面总数：N
- 错误：N
- 警告：N
- 各项检查详情...

### LLM 补充检查
1. 矛盾检查：发现 N 项（详情）
2. 过时声明：发现 N 项（详情）
3. 缺失交叉引用：发现 N 项（详情）
4. 编译真相与时间线一致性：发现 N 项（详情）

### 修复记录
- 已修复：...
- 待用户裁定：...
```

### 第四部分：修复 + 记录

**能直接修复的就修**（§9.3）：
- 悬空引用 → 删除或补建目标页
- 缺失交叉引用 → 补 `[[wikilink]]`
- frontmatter 缺字段 → 补齐
- index 漏登记 → 补登记
- 时间线格式不符 → 修正
- 编译真相与时间线不一致 → 补时间线条目

**需用户裁定的不自动修**：
- 页间矛盾（需用户判断采纳哪方）
- 过时声明（需确认 raw 是否真有更新）

修复后在 `wiki/log.md` 追加一条 `lint` 记录（§11）：

```markdown
### YYYY-MM-DD HH:MM - Lint

- **源文件**：—（全量自检，无新源）
- **触达的 wiki 文件**：wiki/a.md, wiki/b.md, …（修复涉及的页）
- **说明**：共发现 N 项问题，已修复 M 项，待裁定 K 项。详情...
```

## Trae Schedule 自动触发

**权威依据**：AGENTS.md §14.2。

通过 Trae 的 `Schedule` 工具可设定每周自动触发一次 lint。自动化触发的 lint 记为 `lint` 操作类型，说明里标注「Schedule 自动触发」。

若需创建/管理定期 lint 自动化，使用 `Schedule` 工具：
- `action: "list"` — 查看现有自动化
- `action: "create"` — 创建新的定期 lint（需指定 cron_expression、message）
- `action: "trigger"` — 手动触发一次现有任务

## 通用规则（以 AGENTS.md 为准）

以下通用规则不在本 skill 重复，修复时一律以 AGENTS.md 为准：
- frontmatter 必填字段：**§3**
- 双区结构（编译真相重写 / 时间线追加）：**§4.1**
- 交叉引用风格（`[[filename]]` / 禁止相对路径）：**§6**
- 矛盾处理（修正条目 + 重写 + callout）：**§8**
- 引文格式与时间线条目格式：**§7**
- index.md 维护规则：**§10**
- log.md 维护规则：**§11**
